# ADR 004: Pagos con tarjeta (Stripe Checkout) y pago simulado

- **Estado**: Aceptado (pendiente: cuenta de Stripe y llaves en Render)
- **Fecha**: 2026-11-12
- **Contexto previo**: [ADR 002](ADR_002.md) dejó el pago como simulado en el MVP;
  [ADR 003](ADR_003.md) definió el hosting (Vercel + Render + Neon).

## 1. Contexto

El checkout (vista 04) marcaba la orden como PAGADA sin cobrar. Para la siguiente entrega se
necesita un cobro real con tarjeta, sin costo para el equipo y sin manejar datos de tarjeta.
La demo debe seguir funcionando aunque no haya llaves de un proveedor de pago.

## 2. Decisión

**Stripe Checkout en modo de prueba**, detrás de un puerto (arquitectura hexagonal), con el
pago simulado como segundo adaptador.

| `FACFOOD_PASARELA` | Adaptador | Cómo se confirma el pago |
|---|---|---|
| `simulado` (por defecto) | `PagoSimulado` | `POST /ordenes/{id}/pagar`, como antes |
| `stripe` | `PagoStripe` | Aviso firmado de Stripe a `POST /pagos/webhook` |

Flujo con Stripe:

```
Carrito ──POST /ordenes/{id}/checkout──▶ API: revalida y fija el monto, crea la sesión (MXN, 30 min)
   │                                       └─ guarda el pago PENDIENTE (tabla pagos)
   └──▶ página de pago de Stripe ──(tarjeta)──▶ Stripe
                                                 ├─▶ POST /pagos/webhook (firmado) ─▶ orden PAGADA
                                                 └─▶ regresa a /pedido/{id}/pago ─▶ "Confirmando…" hasta verla PAGADA
```

Reglas:

- **El monto lo calcula el servidor** al abrir el cobro (puesto abierto, lealtad actual, cupón
  revalidado) y queda guardado en `pagos.monto`. El cliente nunca manda precios.
- **Solo el webhook marca la orden como pagada**, no el regreso del navegador (se puede falsificar).
- **Webhook autenticado con la firma de Stripe** (`Stripe-Signature`, HMAC-SHA256 con
  `STRIPE_WEBHOOK_SECRET`, máximo 5 min de antigüedad), verificada sobre el cuerpo crudo antes
  de leerlo. Es público porque Stripe no inicia sesión, pero sin firma válida responde 400 y no
  toca nada.
- **Idempotente**: Stripe reintenta los avisos y el mismo puede llegar varias veces. Además se
  comprueba que la orden, la moneda (`mxn`) y el monto coincidan con el pago guardado.
- **Un solo cobro abierto por orden** (índice parcial único en `pagos`). Mientras está abierto la
  orden no se edita (409 `PAGO_EN_CURSO`); `DELETE /ordenes/{id}/checkout` lo cancela.
- **Con `stripe`, `/pagar` se desactiva** (409 `PAGO_EN_LINEA_REQUERIDO`): nadie se salta el cobro.
- **Si el cupón se agota mientras el comprador paga**, se respeta lo cobrado y no se cuenta un uso
  por encima del límite (queda registrado en `usos_cupon`).
- **El RFC se valida antes de cobrar**, no al recibir el aviso.
- **Falla cerrada**: con `stripe` y sin `STRIPE_SECRET_KEY`/`STRIPE_WEBHOOK_SECRET` la API no arranca.
- **Secretos solo en Render**; el repo no guarda ninguna llave.

## 3. Alternativas consideradas

- **Mercado Pago** — popular en México y acepta OXXO, pero su modo de prueba exige usuarios de
  prueba y su documentación de webhooks es menos clara. Se deja como posible segundo adaptador.
- **PayPal** — más fricción para el comprador (cuenta PayPal) y peor experiencia en móvil.
- **Stripe Elements (formulario propio)** — más control visual, pero el formulario corre en
  nuestra página y aumenta el alcance de PCI. Checkout alojado deja la tarjeta solo en Stripe.
- **Solo simulado** — no cumple el objetivo de cobrar de verdad.

## 4. Consecuencias

- **Positivas**: cobro real en modo de prueba a $0 (sin comisiones en prueba), sin datos de
  tarjeta en nuestros servidores, la demo funciona sin llaves y cambiar de proveedor es escribir
  otro adaptador.
- **Riesgos / Limitaciones**:
  - La API de Render se duerme: si el aviso llega dormida, Stripe lo reintenta (en modo de prueba
    pocas veces en unas horas; también se reenvía desde el panel) y la página de regreso muestra
    "Tu pago se está procesando".
  - Fuera de alcance: OXXO/SPEI, reembolsos y pagos divididos a vendedores (Stripe Connect).
    Un cobro que no coincida con la orden queda en la bitácora para reembolsarlo a mano.
  - Pasar a producción (cobros reales) requiere activar la cuenta de Stripe con datos fiscales.

## 5. Cómo se prueba

- **CI, sin red**: pasarela falsa para la lógica del checkout; firma HMAC real generada en la
  prueba para el adaptador; PostgreSQL para la tabla `pagos` y el índice único.
- **A mano**, con la cuenta de prueba: `stripe listen --forward-to localhost:8000/pagos/webhook`
  y la tarjeta `4242 4242 4242 4242` (cualquier fecha futura y CVC). Ver
  [docs/DESPLIEGUE.md §8](docs/DESPLIEGUE.md).
